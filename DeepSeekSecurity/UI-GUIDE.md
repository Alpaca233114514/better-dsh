# DSH 插件 UI 简明规范

1. **插件引用与用户需求分开。** `@deepseek-security` 是无空格的原生引用标签，后面的需求由用户编写。`onPick` 返回 `ReferenceInsert`，不发送消息、不启动扫描，也不替换成整句预设请求。DSH 原生标签已自带 `@`，label 写 `deepseek-security`；复制和发送保留这个名称，内部工具指令不写进用户聊天正文。
2. **发送后由模型调用。** 引用 codec 只保留插件名称，调用说明由 Host 工具描述提供，DSH 保留标签前后的用户文字。`security_scan.instructions` 携带需求、关注点和排除项，传给实际扫描 Agent。
3. **只在执行期间显示进度。** `conversation.input.dock` 默认渲染为空；宿主出现活动扫描后才显示进度框。没有“就绪”或“开始扫描”面板。结束后收起，报告和失败原因留在原生聊天中。
4. **复用原生组件与主题。** 进度框按 DSH TodoPanel 布局，使用原生图标、StateDot 和 Button，正文 13px / 20px、标题 13px / 24px，继承 composer 几何与颜色。默认收起，持续显示当前步骤和本步耗时；展开后展示步骤、活动、文件数和总耗时，步骤区最多 180px 高并可滚动。
5. **状态来自宿主。** Client 正确解包 `RemoteResult<T>` 的 `ok/value/error`，进度只取真实任务阶段。网络错误不能当作就绪；停止失败不能被下一次成功轮询清除。过期响应不能覆盖取消或已切换的会话。
6. **停止随任务。** 进度框调用宿主取消，聊天停止通过 `exec.signal` 向扫描传递取消。等待执行收尾后才结束工具调用；不能在界面已停时继续消耗模型额度。
7. **生命周期与单例。** Client 先挂载 Typert contribution，再注入 `remote.deepseekSecurity`。轮询与组件一起启动/卸载，注册与样式随 Cordis scope 清理。选择引用、观察进度、查看报告都不能隐式启动模型。

验证重点：插入标签后保留需求、发送才执行、真实阶段驱动进度、完成后隐藏、RPC 错误、重复停止、晚到响应、切换会话及重启恢复。

预检细分为检查工作区、枚举仓库文件、记录仓库快照、建立扫描记录、初始化审计工具、等待模型分析，之后展示威胁模型、漏洞检查、候选验证、攻击路径和报告生成。读取/搜索代码与保存检查点由子会话实际事件驱动；计时只表示耗时，不代表活动心跳或完成比例。只把实际经过的阶段标为完成。

收起时直接显示当前动作与相对路径，并保留一行真实活动信息：已成功读取的文件数、成功搜索次数、最近活动距今时间。等待响应与模型分析依据原生流 start/chunk 区分，不展示推理正文；流事件同类每秒最多保存一次，不靠定时器刷新活动时间。动作耗时与最近活动时间分开：分析持续三分钟、刚收到输出，可以同时成立。旧 Host 没有活动字段时只展示其实际支持的阶段信息。

展开/收起、箭头和阶段切换使用 `cubic-bezier(.22, 1, .36, 1)`，过渡 200–300ms；遵循 `prefers-reduced-motion`。当前阶段在展开时滚动到可见位置，折叠不停止扫描。

参考：[Codex Security](https://github.com/openai/codex-security)、[OpenAI 插件技能](https://developers.openai.com/plugins/concepts/skills)。
