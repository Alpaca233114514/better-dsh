# Cyber 安全工作台 · 0.2.1

DSH 左侧导航新增 **Cyber**，在独立主面板中管理安全审计。信息架构与视觉参考用户提供的 OpenAI Daybreak Cloud 截图：克制的主题色、细边框、漏洞分布图、可筛选表格、双栏详情和右侧扫描抽屉。界面为本项目自行实现，没有复制 Cloud 页面源码或资源。现有 OpenAI Codex Security 工作台代码继续按 [许可证声明](LICENSE-DECLARATION.md) 使用。

## 已接入的流程

- **安全发现**：按严重程度和处置状态分流的 SVG 图、文本搜索、严重程度与状态筛选，关联代码位置、证据、验证说明、攻击路径和修复建议。节点文字独立于连线区域，保留间隔。
- **发现详情**：报告／修复建议分栏，侧栏可编辑“新发现、已分诊、处理中、已修复、不修复、重复、误报”七种处置状态，保存后同步列表、图表和历史扫描详情；保留风险、来源仓库、首次发现、出现次数和模型，并可进入来源扫描。
- **修复会话**：“新发现、已分诊、处理中”的发现详情右上角显示“修复”；其他四种已结束处置状态保留“新建扫描”。点击修复后在当前仓库创建普通 DSH 会话，沿用当前工作区模型、推理强度及 Ultra 选择，并发送固定中文模板。模板由宿主从真实报告填入发现编号、标题、严重程度、摘要、代码位置、证据、验证记录、攻击路径、修复建议和来源扫描。模型使用正常会话工具和宿主审核流程执行修改与验证；请求被接受后状态记为“处理中”。
- **Repositories**：从 DSH 会话目录去重获得本地仓库，查看已选仓库的扫描次数、风险和最近扫描时间。
- **Scans**：保存历次任务、状态、范围、模型、耗时、Token 用量和真实阶段时间戳，读取指定历史报告，导出 Markdown 或 findings JSON。
- **New Scan**：选择 DSH 已注册的模型及其公开推理强度，扫描整个工作区或一个相对文件／目录，传递附加需求。点击开始后创建并进入普通 DSH 会话，保留执行转录，完成后的报告与发现同步回 Cyber；扫描详情可重新打开来源会话。只有“开始扫描”会启动审计。
- **Ultra 联动**：已安装 Ultra 插件且原生委派可用时，为支持 Max 的 DeepSeek 模型提供 Ultra 选项。通过 Ultra 服务保存模式，以真实 Max 参数运行并注入原生委派策略；不会将 `ultra` 作为模型推理参数。普通扫描保持顺序执行；Ultra 后代代理只可使用扫描拥有的只读工具和允许的协调工具，不能扩大所选目录范围，收尾等待后代退出。
- **停止与恢复**：沿用工作区单任务和取消后等待执行收尾的机制；切换页面不启动或停止任务，重启将活动任务记为中断，不自动续费运行。

扫描使用现有 DSH AgentLoop 和当前账号的模型路由，不接入 OpenAI Cloud、Codex SDK 或 Daybreak 专用模型。扫描能力为 Standard 静态审计，修复入口则显式发起普通模型编辑会话；没有添加深度扫描、PR／提交扫描、网络攻击、云端仓库克隆、持续监控或定期扫描按钮。

## 数据与范围

状态仍保存在工作区之外的 `stateDirectory/tasks.json`。兼容旧版每工作区一条任务的数组；从 0.2.0 起保留新扫描的历史，不删除或重写已有任务数据的含义。旧版本已经覆盖掉的历史不会凭空恢复。不同工作区的 RPC 只返回本工作区任务及报告；历史报告 ID 也必须属于调用会话的工作区。

Cyber 可直接查看尚未在聊天区打开的仓库。宿主通过 `sessionPersistence.stat` 读取保存的会话头，缓存不可变工作区路径，并合并同一会话的并发读取；不读取会话完整历史，查看报告也不会恢复 Agent 或调用模型。开始扫描时通过 Session Controller 创建独立会话，不激活作为仓库入口的旧聊天。冷会话尚无已加载模型投影时，抽屉使用 DSH 默认模型，并允许用户另选模型。

界面使用 DSH 主界面的背景变量，导航与控件中文化；删除辅助说明、空态正文、列表第二行和重复模型文字。图表高度与文字字号独立于页面宽度，避免宽屏放大连线和标签。初次加载有状态反馈；读取超时或渲染异常显示错误与重试入口。

Findings 使用上游 canonical fingerprint（回退到 findingId）归并同一漏洞，保留首次、最近发现时间和出现次数。人工处置状态按工作区与该指纹保存在 `stateDirectory/finding-statuses.json`，不修改原始扫描报告，同一漏洞再次出现会保留所选状态。所有状态都可再次编辑；“已修复”等标签表示用户的处置记录。一次新扫描没有再次发现某漏洞，不会自动改变其状态。

界面调用的是 DSH 提供的相对 `/api/deepseekSecurity/...` 宿主 RPC，不是 Daybreak 云 API。仅刷新 Client 不能加载新的 Host 接口；宿主通过 dashboard 声明状态编辑能力。旧宿主未加载接口时，界面显示完整重启 DSH 的提示，不调用缺失路由；状态保存失败不覆盖原值，显式重试加载可清除旧错误。

修复 RPC 只接收会话和发现编号，由后端核对所属仓库和可修复状态；客户端不能传入任意提示词、目标目录或发现正文。并发启动同一发现会合并；会话创建成功但导航失败时，重试导航不会重复发送修复。启动失败不会把发现标记为“处理中”；模型输出保留在修复会话，是否最终修复仍由实际验证结果和人工处置决定。新接口也有宿主能力检测。

扫描与修复会话创建时优先使用来源会话所属的原生 `workspaceId`，由 Session Controller 登记会话与工作区分组的关系。没有来源归属时按规范目录匹配已注册工作区；仅当该目录尚无原生工作区时使用 `cwd`。工作目录与分组归属是不同字段，只传 `cwd` 会使新会话落入“未分组”。不同目录即使分组同名也不会混用。

指定范围会写入上游扫描契约，同时限制 read/glob/grep 的实际读取边界；拒绝工作区之外的路径以及符号链接、junction。附加需求中的范围和排除项仍由模型按扫描契约解释，不额外扩张工具权限。

Token 来自扫描会话及本次 Ultra 后代会话的 `assistant/message` 和无表面输出的 `assistant/attempt` 用量事件。输入、输出、缓存读取、缓存写入相加；reasoning 已计入模型输出，不重复相加。缺失用量显示“未报告”，部分调用缺失时标明已知部分。它不是套餐余额或费用估算。时间线只记录实际阶段事件，不能把停留时间当作细粒度工具日志。

## 构建与验证

```powershell
npm ci --ignore-scripts
npm run typecheck
npm run build
npm test
```

浏览器交互验证使用本机已有 Playwright（或设置其模块入口）与 Chromium／Edge：

```powershell
$env:CYBER_PLAYWRIGHT = 'C:/path/to/playwright-core/index.mjs'
$env:CYBER_CHROMIUM = 'C:/Program Files (x86)/Microsoft/Edge/Application/msedge.exe'
node scripts/verify-cyber.mjs
```

浏览器脚本加载真正构建后的 DSH client factory，检查 Cyber 与 main 注册、页面交互、筛选、抽屉、参数传递、RPC 错误、停止、JSON 导出、主题、窄屏和卸载。浏览器数据及模型路由是明确标注的合成夹具，不连接真实模型；不是桌面安装验收或审计能力评测。截图与结构化检查结果保存在 `.cache/cyber-verification/`。

原生扩展接口最低依赖 DSH `0.2.1-rc.2` 的 sidebar/layout 包，宿主仍须满足 package.json 的全部兼容条件。修改宿主后需要完整重启 DSH 才能加载新插件；未通过实际桌面运行验证前，不将类型检查和浏览器夹具写成桌面成功记录。
